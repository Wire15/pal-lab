# Pal Lab 1.8.1

Hotfix for v1.8.0's SFTP feature, found by the first real-world connection.

## Fixed

- **SFTP world scan now handles hosting-provider layouts.** Game hosts
  commonly jail SFTP at a server root, with the world buried at
  `/Pal/Saved/SaveGames/<id>/<world>` — deeper than the old scan reached, so
  the connection succeeded but no worlds were found. The scanner now searches
  up to 6 levels deep with a strict request budget (max 400 directory
  listings), checks well-known folder names first (`Pal`, `Saved`,
  `SaveGames`, steam ids, world GUIDs), and skips noise (`backup`, `logs`,
  dotfolders). Setting REMOTE PATH to `/` on a typical game host now just
  works.
- The "no worlds found" message now names the common path
  (`/Pal/Saved/SaveGames`) so you know what to point at.

No other changes; the web app is unaffected.
