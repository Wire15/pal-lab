# Pal Lab 1.7.0

**The solver now explains itself.**

This release came directly from a user staring at a plan and asking "why is
it breeding two Eidrolon Ignis to make... another Eidrolon Ignis?" The plan
was actually optimal — the solver was washing unwanted passives out of the
breeding line — but nothing in the UI said so. That's a UI failure, not a
user failure. Fixed:

## What's new

- **Per-step odds breakdown.** Every breeding step now shows exactly what
  its egg percentage means: Passives × Move × IVs × Gender → expected eggs.
  Click any node (or use the list view) to see the numbers.
- **"Cleans line" annotation.** Children inherit from *both* parents'
  combined passive pool. When a plan breeds an intermediate purely to shed
  junk passives from the line — so later eggs hit the target more often —
  that node is now labeled, with a plain-English explanation.
- **Extra-passives control.** You decide what counts as junk:
  - "Any" — deliver the pal, I don't care about stray passives. **This is
    now the default when you haven't required any passives**, so a "just get
    me this species with this move" solve returns the fastest direct path,
    never a surprise cleanup step.
  - "≤2 / ≤1 / None" — stricter, cleaner result, more eggs. Default is ≤1
    when you *have* required passives. Your explicit choice persists.
- **More accurate move-inheritance odds.** Owned parents now contribute
  their real equipped inheritable moves to the inheritance pool instead of a
  species estimate. (The ~50% base rate is still community-measured, and
  still labeled that way.)

## Honest notes

- If you liked the old behavior — clean-ish pals by default — set Extra
  passives to ≤1. The solver's math didn't change; the default and the
  explanations did.
- Odds remain estimates. Breeding is random; the tool prices the randomness,
  it doesn't remove it.
